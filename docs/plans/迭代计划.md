# 后续迭代计划

本文档记录 `drission-cloud-driver` 后续迭代方向，优先聚焦当前代码中已经暴露的未实现接口，再推进平台扩展和工程化能力。

## 当前状态

- 服务主体、配置加载、日志、中间件、Driver 注册表、浏览器连接管理已经具备基础框架。
- 当前已注册平台只有 `115`。
- `go test ./...` 可以通过，已经补充基础单元测试。
- README 中部分能力描述比实际实现更靠前，需要在功能补齐或文档修正之间保持同步。

## P0：补齐已暴露 API

这些接口已经在路由或 Driver 接口中暴露，属于优先级最高的缺口。

### 浏览器 Profile 管理

状态：已落地。

目标文件：

- `internal/handler/v1/profile.go`
- `internal/browser/manager.go`
- `internal/cloak/client.go`

待实现：

- `GET /profiles/:id`：获取指定 Profile 详情。
- `POST /profiles/:id/start`：启动指定 Profile。
- `POST /profiles/:id/stop`：停止指定 Profile。

建议实现方式：

- 在 `browser.Manager` 中增加 `GetProfile`、`StartProfile`、`StopProfile` 方法，内部委托给 `cloak.Client`。
- `StopProfile` 成功后同步关闭并清理本地 CDP 连接缓存。
- Handler 返回统一响应结构，失败时记录结构化日志。

验收标准：

- 三个接口不再返回 `501 not implemented`。
- CloakBrowser-Manager 返回错误时能透传可读错误信息。
- 停止 Profile 后，本地连接缓存被释放。

### 115 文件管理能力

状态：已落地。

目标文件：

- `internal/drivers/pan115/driver.go`

待实现：

- `Remove`：删除文件或目录。
- `Move`：移动文件或目录。
- `Rename`：重命名文件或目录。
- `GetDownloadURL`：获取文件下载直链。

建议实现方式：

- 优先复用 `115driver` SDK 已提供的方法。
- 如果 SDK 不支持某些能力，再封装对应 Web API 或通过浏览器上下文执行必要操作。
- 补齐路径到文件 ID 的解析能力，避免只支持目录路径。
- 对根目录、空路径、目标重名、文件不存在等边界场景返回明确错误。

验收标准：

- README 中列出的文件系统与媒体接口均有真实实现。
- 操作失败时不会只返回笼统的 `not implemented` 或 `internal server error`。
- 对 115 的目录和文件都能正确解析 ID。

## P1：统一 API 响应与错误处理

状态：已落地。

目标文件：

- `internal/pkg/response/response.go`
- `internal/pkg/errcode/errcode.go`
- `internal/handler/v1/*.go`

待实现：

- 将 handler 中直接使用 `gin.H` 的响应逐步替换为 `response.Success`、`response.Error`、`response.AppErr`。
- Driver、Profile、Cloak、Browser 相关错误映射到已有业务错误码。
- 对参数校验错误使用统一的 validation response。

验收标准：

- 成功响应统一为 `{ "code": 0, "message": "success", "data": ... }`。
- 错误响应包含稳定业务码，前端无需解析英文错误字符串。
- README 中的统一响应格式和实际接口保持一致。
